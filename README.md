# 沖繩行程（動態資料版）

頁面只負責顯示；**行程資料全部由 Google Apps Script（okinawaTrip）提供**，來源是 Google 試算表 okinawa-trip-gas。
改行程只要改試算表，重新整理網頁即可，不需要改程式或重新上傳網頁。

## 檔案結構

```
okinawa-trip/
├── index.html              我的行程：只顯示地點管理「確認」送出的行程（原本的「行程地圖」頁已移除）
├── places.html             地點管理（搜尋 Google Maps 景點 → 匯入清單 → 安排到第 1～5 天）
├── css/                    樣式（tokens.css 集中所有顏色、字級、間距）
└── js/
    ├── config.js           設定：資料來源 api.url、介面文字、地圖寬度…（最先載入）
    ├── myplan-mode.js      index.html 用：讓 loader.js 改讀 action=myplan
    ├── myplan-build.js     index.html 用：Apps Script 尚未支援 action=myplan 時，在網頁端組出我的行程
    ├── loader.js           向 Apps Script 取得行程 → 載入 lib/ 與 app.js；失敗時顯示錯誤與「重新載入」
    ├── lib/                功能模組：地圖、景色圖卡、選單與行程清單的 HTML
    │   └── map-gl.js       我的行程專用：MapLibre＋OpenFreeMap 真實底圖（失敗時自動改用 SVG 地圖）
    ├── app.js              啟動：建立畫面、天數切換、交通方式、收合、深淺色
    └── places/             地點管理頁
        ├── poi-logic.js    匯入與安排的規則（與 Apps Script 的 PoiLogic.gs 相同）
        ├── demo-data.js    示範資料（模擬，沒有 API 金鑰時使用）
        ├── store.js        讀寫資料：Apps Script（試算表）或離線示範
        └── app.js          畫面與操作
```

## 設定

1. Apps Script 專案 okinawaTrip 部署為網頁應用程式（執行身分：我；誰可以存取：任何人），複製 `…/exec` 網址。
2. 貼到 `js/config.js` 的 `api.url`。
3. 開啟 `index.html`。

| 設定 | 說明 |
|---|---|
| `api.url` | Apps Script 網址（必填） |
| `api.code` | 預設顯示的行程代碼（試算表 `itinerary.code`） |
| `api.timeout` | 等待毫秒數，預設 15000 |
| `api.writeToken` | 地點管理的寫入密碼，需與指令碼屬性 `WRITE_TOKEN` 相同（沒設定 `WRITE_TOKEN` 可留空） |
| 網址 `?code=…` | 切換行程，例如 `index.html?code=okinawa-5d` |

頁面標題、選單的「N 天行程」、全島小圖範圍都依資料自動產生。

### 部署的「誰可以存取」

| 設定 | 誰看得到網頁的行程 |
|---|---|
| 任何人 | 所有人（建議） |
| 網域中的使用者（besttour.com.tw） | 只有在瀏覽器已登入公司 Google 帳號的人（loader.js 會自動改用 JSONP 讀取） |
| 只有我自己 | 只有你本人已登入的瀏覽器 |

沒有權限時，畫面上方會顯示「需要登入或沒有存取權限」。

## 要改行程時，改試算表的哪裡

| 想改什麼 | 頁籤 |
|---|---|
| 行程名稱、狀態 | `itinerary` |
| 某天的標題、說明、底部說明、地圖範圍、比例尺、全島小圖紅框 | `itinerary_day` |
| 某天去哪些地點、順序 | `day_stop`（地點本身在 `place`） |
| 地點名稱、地址、座標、景色插圖、照片 | `place`（市町村在 `city`） |
| 交通方式、統計數字、導航按鈕 | `day_mode`、`mode_stat`、`mode_button` |
| 路段的距離、時間、路線說明 | `leg`（路線座標在 `shape_point`） |
| 地圖上的道路、河流、地名 | `map_layer`、`map_label`、`shape_point` |

代號 A/B/C、出發／終點、「N 個地點」、完整地址等由 Apps Script 自動計算，不需要填。
各欄位的意義與規則見試算表的 `_schema` 頁籤。

## 地點管理（places.html）

從我的行程左側選單「地點管理」進入；左上角「我的行程」返回。三個分頁：

1. **景點搜尋**：地區（預設沖繩）、評分（預設 4 星以上）、類型（觀光景點／自然景觀／文化古蹟／購物中心）。
   景點搜尋與地點清單是同一批景點（原行程地點＋地點清單），不再有「加入地點」；在卡片上「選擇天數＋加入」即可排進行程。
2. **地點清單**：完整資訊、自訂備註、刪除、安排到第 1～5 天，並顯示已安排在哪天。
3. **行程安排**：依天分組，可調整順序、移到其他天、移出行程（景點仍保留）。
   上方有 **「全部清除」** 和 **「確認」**：「景點搜尋」卡片的「加入」，以及這一頁的調整都先暫存在畫面上（頁籤出現黃點、上方顯示「尚未儲存」），
   按 **「確認」** 才一次寫入試算表 `poi_schedule`；「全部清除」也要按「確認」才生效，按「放棄變更」可還原成試算表的內容。
   有未儲存的變更時離開頁面會先提醒。

規則：
- 「匯入景點」與「安排到行程」是兩個步驟；同一景點同一天只能出現一次。
- 已安排在其他天時，會詢問「移動到第 N 天」或「保留原安排」。
- 景點以 Google Place ID 判斷重複；手動新增的以「名稱＋地址」判斷。
- 沒有評分的景點不會出現在「N 星以上」的結果中。

### 資料寫在試算表哪裡

| 頁籤 | 內容 |
|---|---|
| `poi` | 匯入的景點（一個景點一列，`google_place_id` 不重複） |
| `poi_schedule` | 景點安排在哪個行程的第幾天、第幾個（`poi_id` → `poi`） |

第一次讀取時 Apps Script 會自動建立這兩個頁籤，並登錄到 `_tables`、`_schema`。

### Google Maps API 金鑰（只放在 Apps Script，不放在網頁）

1. Google Cloud Console → 啟用 **Places API (New)** → 建立 API 金鑰，限制只能呼叫 Places API (New)。
2. Apps Script →「專案設定 → 指令碼屬性」新增 `PLACES_API_KEY` = 金鑰。
3. （建議）新增 `WRITE_TOKEN` = 自訂密碼，並填到 `js/config.js` 的 `api.writeToken`。
4. 「部署 → 管理部署作業 → 編輯 → 版本：新版本 → 部署」。

沒有金鑰時，搜尋區會顯示「無法使用 Google Maps 搜尋」，只列出目前所有景點（原行程地點＋地點清單），可在地點清單 **手動新增**。照片只在搜尋結果顯示（附攝影者署名），不會存進試算表。

### 離線示範

`js/config.js` 的 `api.url` 留空，或讀取 Apps Script 失敗時按「改用離線示範」，
資料只存在這個瀏覽器，不會寫入試算表；頁首會顯示「離線示範」。

### 行程景點排序（原行程地點＋新增景點同一份清單）

- 「行程安排」每天只有一個「行程景點排序」清單：原行程的地點（`day_stop`）與新增景點（`poi`）一起排序，
  都可以上移、下移、移到第幾個、移到其他天、移出行程；序號自動重新編排。
- 排序資料存在試算表 `poi_schedule`：每列有唯一的 `schedule_id`，`day_stop_id`（原行程地點）或 `poi_id`（新增景點）擇一，
  `sort_order` 是當天順序；原行程地點「移出行程」時 `hidden = TRUE`（`day_stop` 原始資料不刪，可在當天下方「加回」）。
  舊版的 `poi_schedule` 會在第一次寫入時自動補上 `sort_order`、`day_stop_id`、`hidden` 欄位。
- 我的行程（index.html）依同一份排序顯示地點、路段、地圖範圍與活動範圍。
  沒有座標的新增景點不會畫在地圖上（排序清單會標「無座標」）。
- 出發地、終點的位置限制獨立設定：Apps Script「指令碼屬性」新增 `PLAN_RULES`，例如
  `{"startFirst":true,"endLast":true}`；沒設定時可以自由排序。

### 按「確認」時更新的資料表

| 資料表 | 更新內容 |
|---|---|
| `poi_schedule` | 行程景點排序（原行程地點＋新增景點）的天數、`sort_order`、`hidden` |
| `poi` | 暫存的新地點（有的話） |
| `day_stop`（原行程列表） | 原行程地點的 `day_id`、`seq`、`hidden`；第一次同步時把原本的天數與順序記到 `orig_day_id`、`orig_seq` |

`day_stop` 的移出地點不會刪除（`hidden = TRUE`，排在當天最後）。行程地圖判斷路段（`leg`）是否仍適用時，比對的是 `orig_day_id`、`orig_seq`：
順序和原始相同就顯示原路線，不同就改成直線示意。新增景點不會寫入 `day_stop`。

## 我的行程（index.html）

首頁。**不帶入試算表原本的行程**（原本的「行程地圖」頁已移除），只顯示地點管理頁「行程安排」按「確認」送出的結果：

- 資料來源：Apps Script `?action=myplan`（`Itinerary.gs` 的 `buildMyPlan`），只讀 `poi_schedule` 已儲存、未移出的資料，依 `sort_order` 排序。
- 送出時保留在行程中的原行程地點會出現（只用地點名稱、地址、座標）；原路線、道路、地名圖層、說明文字都不帶入。
- 路段一律為兩點間的直線示意；地圖範圍、「5 天行程」選單、行程與路段、活動範圍都依送出的地點計算。
- 沒有安排地點的天數顯示「尚未安排地點」；一次都還沒送出時，頁面上方會提示到地點管理安排。
- 在地點管理按「確認」後，開著的我的行程會自動重新讀取。
- Apps Script 已更新（`Api.gs`、`Itinerary.gs`、`PoiStore.gs`）時由 `?action=myplan` 取得；還沒更新時，`js/myplan-build.js` 改讀既有的 `action=places`、`table=poi_schedule`、`action=itinerary`（只取地理資料），在網頁端組出相同內容。

### 我的行程的地圖（MapLibre 試做版）

- 底圖：OpenFreeMap（OpenStreetMap 資料，免費、不需金鑰），淺色 `positron`、深色 `dark`，跟著深淺色切換。
- MapLibre GL JS 4.7.1 由 unpkg 載入（`js/loader.js` 的 `MAPLIBRE`）；由 `index.html` 載入（`js/myplan-mode.js` 設定 `mapEngine: 'maplibre'`）。
- 地點圓點 A/B/C 可點開景色圖卡；地名每次移動後自動挑右／左／上／下避開重疊，放不下的先隱藏，放大後出現。
- 可拖曳、縮放（電腦需按 Ctrl／⌘ 加滾輪，手機用兩指）、重設範圍；滑過右側路段會在地圖上標示。
- 路段仍是兩點間直線示意（真實路線是下一步）。
- MapLibre 載入失敗、瀏覽器不支援 WebGL、或 15 秒內讀不到底圖時，自動改回原本的 SVG 地圖。

## 載入速度

- **記住上次的資料**：我的行程讀到的資料存在瀏覽器（localStorage，30 天），下次開啟先立刻顯示，同時在背景讀最新資料；
  有變動會自動重新載入一次，左側連線狀態在背景讀取時顯示「更新中…」。地點管理按「確認」後開啟的我的行程會直接讀最新資料。
- **Apps Script 先算好**：按「確認」時 `handleWrite_` 直接用剛寫入的資料重算我的行程並放進暫存（6 小時）；
  不常變動的部分（天數、原行程地點、全島地理）另外暫存 6 小時。一般開啟只讀暫存，按「重新整理」才重讀試算表。
- **同時下載**：MapLibre 與頁面程式在等 Apps Script 回應時就先下載；Google 字型改成不擋住畫面。

## 景點照片

- 大小：照片檔案上限 1 MB（JPG、PNG、WebP），超過會提示先縮小；上傳前再縮成長邊 1000px。
- 存放位置：雲端硬碟 `images` 資料夾（Apps Script `Config.gs` 的 `PHOTO_FOLDER_ID`）。
- 上傳：
  - 「景點搜尋」每張結果卡片的「編輯」、以及「手動新增」表單都有照片欄位。
    已在地點清單或目前行程的地點按「儲存」就上傳；還沒加入或還沒儲存的地點，按「確認」儲存後自動上傳。
  - 「行程安排」每列左邊的小縮圖只能預覽（點一下放大）。
  網頁先縮小（長邊 1000px、WebP，不支援時用 JPG），再送到 Apps Script 存檔。
- 網址寫回試算表：新增景點寫在 `poi.photo_url`，原行程地點寫在 `place.photo_url`（同一個地點在不同天會一起更新）。
- 我的行程點地點圓點時，景色圖卡改顯示照片。
- 換照片時舊檔不刪除，留在資料夾中；尚未按「確認」儲存的新地點不能上傳照片。
- 第一次使用前，在 Apps Script 編輯器執行 `checkSetup` 並允許「雲端硬碟」權限，再部署新版本。

## 景點搜尋：編輯

每張搜尋結果卡片都有「編輯」，可改名稱、地址、座標、備註、照片：

| 地點狀態 | 按「儲存」後 |
|---|---|
| 還沒加入地點清單 | 只改頁面上的搜尋結果；排進行程後按「確認」才寫入 |
| 已加入但還沒儲存 | 改暫存資料，按「確認」時一起寫入（照片隨後上傳） |
| 已在地點清單（poi） | 直接更新試算表 poi 頁籤（`updatePoi`），照片立即上傳 |
| 目前行程（place） | 直接更新試算表 place 頁籤的名稱、座標（`updatePlace`），照片立即上傳；地址請在試算表修改 |

## 地點清單卡片

只保留「選擇天數＋加入」與「刪除」（排在一起）。備註、照片改在「景點搜尋」每張卡片的「編輯」修改；備註可在卡片「完整資訊」查看。

## 景點搜尋：預設畫面

打開「景點搜尋」就列出目前所有景點（目前行程＋地點清單，含尚未儲存的），並套用畫面上的地區、評分、類型；
預設條件為「不限」評分、「全部類型」。改評分或類型時清單立即重新篩選。
有 Google 金鑰時按「搜尋」或「用 Google Maps 搜尋更多」會加上 Google 結果（名稱相同的以 Google 為準）。

## 景點搜尋：地區下拉選單、編輯欄位

- 搜尋地區改成下拉選單：沖繩（全部）、那霸、中部、北部、南部、宮古島、石垣島。
  目前景點依名稱、地址裡的地名關鍵字判斷所屬地區（`js/places/store.js` 的 `REGION_KEYWORDS`，可自行增補）。
- 「編輯」可修改：名稱、地址、座標、類型、評分、Google 地圖連結、備註、照片。
  目前行程的地點（place 頁籤）會自動補上 `rating`、`category`、`maps_url`、`note` 欄位；地址仍請在試算表修改。

## 活動範圍小圖

資訊卡右欄的小圖改用 MapLibre 真實底圖（`js/lib/map-gl.js` 的 `overview`）：
範圍依整趟行程所有地點自動決定（四周留白、至少約 50 公里），紅框是當天範圍，地名由底圖顯示，
所以日本、韓國、新加坡、中國等任何國家都適用。MapLibre 或底圖無法使用時改回原本的 SVG 小圖（只有沖繩有海岸線資料）。

## 地點清單：編輯、手動新增、照片（取代先前「景點搜尋」的編輯）

- 「景點搜尋」只負責找景點並排進行程，不再有「編輯」與「手動新增」。
- 「地點清單」上方有「手動新增」（可附照片）；每張卡片頂端顯示照片（沒有就顯示「沒有照片」），
  按鈕：選擇天數＋加入、編輯、刪除。編輯可改名稱、地址、座標、類型、評分、Google 地圖連結、備註、照片。

## 景點搜尋：選擇天數＋加入；照片同步

- 每張搜尋結果卡片可直接「選擇天數＋加入」：還不在地點清單的會先加入地點清單（暫存），再排進那一天；同名的地點已在清單中就直接用它。
- 地點清單卡片只剩「編輯」「刪除」。
- 加入地點時，自己的照片（雲端硬碟，例如原行程地點的照片）會一起帶進地點清單；Google 搜尋結果的照片依 Google 規範不保存。
- 名稱相同時，目前景點以地點清單（poi）為準顯示。

## 景點搜尋與地點清單同步（20261018e）

- 「景點搜尋」不再區分「原行程景點」與「示範資料」，也不再有模擬景點：預設列出全部景點（原行程地點＋地點清單），依搜尋條件篩選。
- 移除「全選」、勾選框與「加入地點」。Google Maps 搜尋結果用「選擇天數＋加入」排進行程時，會自動加入地點清單。
- 「地點清單」顯示同一批景點：原行程地點（試算表 place）也列在這裡，可「編輯」、可「刪除」。
- 刪除原行程地點：這個行程中用到它的 day_stop 標為 `removed = TRUE`、`hidden = TRUE`（day_stop 頁籤會自動補上 removed 欄），poi_schedule 中對應的排序資料移除；place 頁籤的資料保留。「我的行程」也會同步拿掉。
- 需要更新的 Apps Script：PoiStore.gs（deletePlace_）、Itinerary.gs、Api.gs、Config.gs（CODE_BUILD 20261018e）。

## 同一個景點可以安排在不同天

- 在「景點搜尋」卡片「選擇天數＋加入」時，景點已排在其他天也會直接加入（不再詢問移動或保留），同一景點可以在多天重複出現。
- 同一天不能重複安排同一個景點。
- 卡片上的「已安排：第 N 天」會列出所有天數（原行程地點與同名的地點清單景點一起計算）。

## 「已移出地點」在「確認」時清除歷史資料（20261018e）

- 行程安排中「移出行程」的原行程地點，會先放在當天的「已移出地點」，按「確認」前都可以「加回」。
- 按「確認」後，「已移出地點」清單會清空，但資料不會刪除：poi_schedule 的這些資料列標為 `archived = TRUE`，並記下 `archived_at`（清除時間）。網頁與我的行程都不再讀取 archived 的資料列。
- day_stop 保留 `hidden = TRUE`，之後不會自動排回行程；地點本身仍在「地點清單」，可從「景點搜尋」再加入。
- 在地點清單刪除原行程地點時，它的排序資料一樣只標 archived，不刪除。
- 要復原：在試算表把該列的 `archived` 清空（或改 FALSE）、`hidden` 改 FALSE，並把 day_stop 對應列的 `hidden` 改 FALSE。
